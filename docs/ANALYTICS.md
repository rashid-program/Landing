# Статистика поведения на сайте

Дата внедрения: 15 сентября 2026 года.

Собственный сбор без внешних счётчиков: данные не покидают сервер проекта.
Решение принято под требование `LEGAL_152FZ.md` — до баннера согласия сайт не
должен загружать сторонние трекеры.

## Что не собирается

- cookies и любые постоянные идентификаторы посетителя;
- IP-адрес и user-agent — их нет в записях, только в стандартных логах веб-сервера;
- имя, телефон, почта и другие персональные данные — на странице нет формы,
  контакт происходит уходом в Telegram или WhatsApp;
- содержимое полей и текст, который посетитель выделял или вводил.

Идентификатор сессии случайный, хранится в `sessionStorage` и исчезает вместе
с вкладкой. Связать два визита одного человека по этим данным нельзя — это
осознанное ограничение, а не недоработка: цена за отсутствие согласия.

Посетитель с включённым Do Not Track или Global Privacy Control не попадает в
статистику вообще: скрипт завершается, не отправив ни одного запроса.

## Что собирается

| Событие | Когда | Зачем |
|---|---|---|
| `page_view` | загрузка страницы | сколько визитов |
| `section_view` | блок задержался на экране дольше секунды | где заканчивают читать |
| `scroll_depth` | пройдено 25 / 50 / 75 / 100 % страницы | глубина прокрутки |
| `cta_click` | нажата кнопка записи | какая кнопка работает |
| `messenger_click` | нажат Telegram или WhatsApp | главная конверсия |
| `faq_open` | раскрыт вопрос | какие возражения важны |
| `reviews_more` | нажато «показать ещё отзывы» | интерес к отзывам |
| `session_end` | уход со страницы | сколько времени провели |

Дополнительно к каждому событию пишутся: тип устройства (телефон / планшет /
компьютер), домен источника перехода и метки `utm_source` / `utm_medium`.

## Как устроено

```
public/analytics.js   собирает события, шлёт батчами (раз в 15 с и при уходе)
      ↓ POST /api/events         — 204 без тела, sendBeacon при закрытии вкладки
server/analytics-store.js        — проверка по списку разрешённых событий, NDJSON
server/data/analytics/ГГГГ-ММ-ДД.ndjson   — по файлу на сутки, в git не попадает
      ↓ GET /api/stats?days=N
server/stats.html     — панель, открывается по /stats (токен вводится в форму)
```

Приём событий защищён проверкой origin и ограничением 30 запросов в минуту с
адреса. Имена событий проверяются по списку: всё незнакомое отбрасывается
молча. Строки обрезаются, управляющие символы вычищаются. Дневной файл
перестаёт расти после 8 МБ, чтобы поток мусора не забил диск.

## Доступ к панели

Токен задаётся переменной окружения `STATS_TOKEN`:

```
STATS_TOKEN=длинная-случайная-строка npm start
```

Открыть `http://<адрес>/stats` и ввести токен в форму. Он сохраняется в
`sessionStorage` до закрытия вкладки и уходит на сервер заголовком
`X-Stats-Token`. В адресе страницы токена нет намеренно: оттуда он попадал бы
в логи сервера и прокси, историю браузера и в любую пересланную ссылку.

Страница `/stats` отдаётся всем, но своих данных не содержит — без верного
токена `/api/stats` отвечает 404 (не 403, чтобы не подтверждать наличие
данных). Сравнение токена постоянное по времени.

Панель держит свой скрипт внутри страницы, поэтому для неё выдаётся отдельный
CSP с одноразовым nonce вместо общего `script-src 'self'`.

## Проверка

```
cd server && npm test          # 11 тестов: приватность заявок и отбор событий
node e2e-analytics.mjs         # три визита в настоящем браузере и сводка
node e2e-signin.mjs            # вход в панель и проверка, что токен не в адресе
```

## Что осталось

1. **Яндекс.Метрика** даст то, чего своя статистика не покажет: регион,
   новый или вернувшийся посетитель, записи сессий, связка с Директом.
   Требует баннера согласия из `LEGAL_152FZ.md` и правки CSP.
2. **Хранение** сейчас файловое. Если визитов станет больше нескольких тысяч
   в сутки, сведение за 90 дней начнёт заметно тормозить — тогда нужна база.
3. **Срок хранения** не ограничен. Стоит решить, через сколько месяцев
   удалять старые файлы, и добавить очистку.
